# 코치 설계 노트

`coach/` 패키지는 면접이 끝난 뒤의 세 가지를 만든다: 코치 노트, 맞춤 연습 힌트, 리포트 3·4번 칸(다듬은 말·다음 연습 계획). 세 곳 모두 원칙이 같다.

## 공통 원칙

- **무엇을 할지는 코드가, 말은 AI가.** 실행할 조언(다음 한 걸음 카드, 일상 미션, 연습할 질문, 다듬을 대답)은 코드가 정하고, AI는 따뜻한 말(인사·"해낸 것"·인용, 힌트 문구, 다듬은 문장)만 쓴다.
- **AI 출력은 전부 검증한다.** 길이, 평가·진단처럼 들리는 표현, 인용이 실제 대답에 있는지, 원래 대답에 없는 내용을 더하지 않았는지를 확인하고, 통과하지 못하면 대체 문구로 바꾼다. 그래서 결과는 항상 완성된 채로 나온다.
- **로그에는 예외 종류만 남긴다.** 면접 대답은 민감정보라 내용을 로그에 남기지 않는다. 다른 AI 코드(`step1/llm_feedback.py`, `step3/interview_question.py`)와 같은 규칙이다.
- **패키지 경계.** DB 조회는 app.py가 `facts`로 모아 넘기고, AI 호출은 각 모듈의 한 함수에만 둔다. 나머지 순수 로직(검증·안전장치·대체 노트·미션)은 DB·AI 없이 테스트한다. 나중에 별도 저장소(ai-agent)로 옮기기 쉽게 app.py나 DB에 기대는 코드를 이 패키지에 넣지 않는다.

## facts 모양 (app.py가 DB에서 모아 넘김)

```
{
  "session":  {"id": int, "tier": str, "completed": bool,
               "turns": [{"kind": "main"|"follow_up", "question": str, "answer": str}]},
  "previous_sessions": [{"id": int, "tier": str, "completed": bool, "question_count": int,
                         "answered_count": int}],          # 최근 순, 이번 면접 제외
  "stage_scores": {"stage1": {축: 0~100} | None, "stage2": {축: 0~100} | None},
}
```

## 에이전트 도구 (`coach/tools.py`)

도구는 app.py가 미리 모아 둔 `facts`를 들여다보는 얇은 창이다. 도구가 user_id 같은 인자를 받지 않는 게 핵심이다. `facts`에 이미 **그 면접의 주인** 것만 담겨 있어서, 에이전트가 다른 사용자의 데이터를 조회할 방법이 구조적으로 없다. 1·2단계 점수도 숫자 대신 "기록 여부와 약한 영역 이름"만 준다. 숫자를 모르면 AI가 점수를 말해 버릴 수도 없다.

## 안전장치 (`coach/safety.py`)

1. **위기 신호 감지** — 대답에 자해·극단적 표현이 있으면 코칭이 아니라 돌봄 안내로 넘어가고 AI를 부르지 않는다. 그 내용을 AI로 보내지도 않고, AI가 코칭하는 말투로 응답하지도 못하게 하려는 것이다. 다만 **키워드 방식의 최선 노력일 뿐 임상적 판단이 아니다.** 못 잡는 표현이 많다. 확정된 위기 대응 절차와 안내 기관은 팀이 정해야 해서, 연락처를 코드에 임의로 넣지 않고 환경변수 `CARE_RESOURCES`로 받는다.
2. **금지어** — 평가·진단처럼 들리는 표현이 AI 출력에 섞이면 그 문구를 버린다. 재활 플랫폼이라 점수·병명·"부족" 같은 말로 사용자를 규정하면 안 된다.

## 일상 미션 (`coach/missions.py`)

면접 밖에서 해 볼 아주 작은 행동 목록이다(노출 연습의 단계). **초안이라 전문가(상담사·현장 경험자)의 검토를 받기 전에는 확정하지 않는다.** AI는 미션을 새로 만들지 않고 이 목록에서 고르기만 한다. 검증되지 않은 조언이 AI에게서 새로 생기지 않게 하려는 것이다.

## 맞춤 연습 (`coach/practice.py`)

- 한 번 더 답해 볼 질문은 "못했다"는 평가가 아니라 "한 번 더 해 볼 만한" 질문을 고르는 것이다. 답을 못 남긴 질문이 있으면 그중 첫 번째, 없으면 가장 짧게 답한 질문(동점이면 앞선 것)을 고른다.
- 힌트는 **답을 대신 써 주지 않는다.** 말하는 순서와 빈칸이 있는 시작 문장 틀만 주고, 사용자의 경험을 AI가 지어내지 못하게 한다.
- 호출 횟수 제한은 메모리에 둔다. 서버가 workers=1이라 프로세스 안에서 충분하고, 재배포하면 초기화되지만 비용 폭주를 막는 용도로는 이걸로 충분하다.

## 리포트 3·4번 칸 (`coach/report.py`)

어떤 대답을 다듬을지는 브라우저가 보낸 질문별 말버릇·멈춤 숫자와 서버의 대답 글로 코드가 고른다(말버릇 표시는 브라우저가 만들어서 서버에는 숫자가 없다). AI가 실패하면 빈 다듬은 말·빈 계획을 돌려주고, 프론트가 "내가 한 말"과 기본 팁으로 대신 보여 준다.

## 노트 구성 (`coach/schema.py`)

- '연습' 카드: 방금 면접에서 한 번 더 답해 볼 질문이 있으면 맞춤 연습 화면(그 질문을 힌트와 함께 다시 답하기)으로, 없으면(질문이 하나도 없는 비정상 면접) 예전처럼 1·2단계 연습 화면으로 보낸다. 점수나 약한 부분의 이름은 문구에 넣지 않는다.
- 인용: 실제 대답에 그대로 있는 문장일 때만 쓴다. 사용자 자신의 말이라도 평가·부정적 표현이 들어 있으면 칭찬 근거로 되돌려주지 않는다.
