# 공통 모듈 설계 노트

여러 단계가 같이 쓰는 작은 모듈의 원인 추적 기록이다.

## AI 호출 도우미 (`llm_util.py`)

effort(생각·토큰 사용량) 설정을 `messages.create(output_config=...)`처럼 키워드 인자로 직접 넘기면, requirements.txt가 고정한 anthropic==0.69.0에는 그 인자가 없어서 요청을 보내기도 전에 `TypeError`가 난다. 그런데 호출하는 쪽이 `except Exception`으로 고정 문구에 넘어가는 구조라, **에러가 삼켜져서 AI가 한 번도 쓰이지 않는데 아무도 모르는** 상태가 됐다. 질문 생성과 1단계 코칭이 실제로 그랬다.

`extra_body`는 모든 SDK 버전에서 요청 본문에 그대로 합쳐지므로 안전하다. 그래서 effort 설정은 이 도우미로만 넘긴다.

## DB 주소 정리 (`db_url.py`)

SQLAlchemy는 드라이버를 적지 않은 `postgresql://`에 "기본 드라이버"를 붙이는데, 2.1부터 그 기본값이 psycopg2에서 psycopg(v3)로 바뀌었다. 이 프로젝트는 psycopg2-binary만 설치하므로, SQLAlchemy 버전을 고정하지 않은 채 배포하면 어느 날부터 빌드가 `ModuleNotFoundError: No module named 'psycopg'`로 죽는다. 2026-10 Render 배포 실패의 원인이 이것이었다.

그래서 SQLAlchemy 버전에 기본값을 맡기지 않고 드라이버를 psycopg2로 못 박는다. Render가 주는 주소는 `postgres://`(SQLAlchemy 1.4부터 버린 형식)이고, 로컬이나 수동 입력은 드라이버 없는 `postgresql://`이라 둘 다 psycopg2로 맞춘다.

## 서버 (`app.py`)

### 무거운 라이브러리는 쓰는 함수 안에서 불러온다

torch·whisper와 2단계의 mediapipe·cv2는 그것만으로 수백 MB를 차지한다. 그런데 `/health`·로그인·커뮤니티처럼 이 라이브러리가 전혀 필요 없는 API도 같은 서버 프로세스에서 돌기 때문에, 파일 맨 위에서 불러오면 그 API만 받는 프로세스도 이 메모리를 늘 쓴다. 배포 환경의 메모리 제한 때문에 2026-09에 모델을 쓰는 함수(`load_models()`, `analyze_gaze_blink()`) 안으로 옮겼다. 2단계 모듈 중 numpy만 쓰는 것(깜빡임·표정·점수·기준값)은 가벼워서 맨 위에 그대로 둔다.

### 표 만들기와 모델 불러오기를 `__main__` 밖으로 뺀 이유

예전에는 `db.create_all()`과 `load_models()`가 `if __name__ == '__main__':` 안에서만 불렸다. 배포에서는 gunicorn이 이 파일을 불러오기만 하고 `__main__`을 거치지 않아서, 표가 한 번도 만들어지지 않아 DB를 쓰는 API가 모두 깨졌고 모델도 계속 비어 있었다. 그래서 표는 파일을 불러오는 시점(프로세스 시작 시 한 번)에 만들고, 모델은 그것을 쓰는 API(`/analyze`, `/api/stage1/calibrate`, `/interview/transcribe`)가 맨 앞에서 `load_models()`를 불러 처음 한 번만 올린다. 실행 방식(개발 서버·gunicorn)과 상관없이 똑같이 동작한다.

### 모델 미리 불러오기 (`PRELOAD_MODELS`)

처음 필요할 때 불러오면 첫 사용자가 1단계 마이크 확인에서 torch·CNN·Whisper가 다 올라갈 때까지 1~3분을 기다린다. `PRELOAD_MODELS=1`이면 서버가 켜지자마자 뒤에서 미리 불러 둔다. 다만 무료 플랜(512MB)에서 켜면 켜지자마자 메모리 초과로 서버가 꺼지므로 2GB 이상에서만 켠다. 기본은 꺼짐이다. 미리 불러오는 중에 요청이 들어와도 반쯤 불린 모델을 쓰지 않게 잠금(`_models_lock`)으로 먼저 온 쪽이 끝날 때까지 기다린다.

### 게스트 계정 (`/api/guest`)

1·2·3단계 API(하루 대화, 2단계 저장, 면접 기록, 코치 노트)는 기록을 사람별로 묶고 AI 호출을 사람별로 제한하려고 로그인을 요구한다. 로그인 없이 시작하게 하려고 그 API를 하나하나 풀면 기록을 묶을 곳이 없어서, 대신 이름 없는 계정을 만들어 토큰을 준다. 이후 흐름은 로그인한 사용자와 똑같다.

- User 표를 그대로 쓴다. 마이그레이션 도구가 없어 기존 DB에 칸을 붙일 수 없어서, 게스트는 이메일 도메인으로 구분한다. `.invalid`는 실제로 쓸 수 없는 예약 도메인(RFC 2606)이라 진짜 메일과 겹치지 않고, 비밀번호는 아무도 모르는 무작위 값이라 이 계정으로 로그인할 수는 없다.
- 토큰은 30일이다. 게스트는 다시 로그인할 방법이 없어 토큰이 만료되면 기록을 이어 볼 수 없으므로 로그인 토큰(7일)보다 길게 두되, 버려진 토큰이 무기한 살아 있지 않게 기간은 둔다.
- 계정이 끝없이 만들어지지 않게 IP당 시간당 20개로 막는다. 같은 와이파이를 쓰는 여러 명을 고려한 값이다.

### 이전 기록

- 1단계 결과는 예전에 프론트 localStorage에만 있어서 서버가 값을 알 수 없었고, 2단계 결과도 기기가 바뀌면 사라졌다. 그래서 둘 다 사용자별 DB 표(Stage1Result·Stage2Result)로 옮겼다.
- 2단계 통화의 목소리 점수는 Stage1Result에 단계 칸을 더하면 이미 배포된 DB에 `create_all`로 반영되지 않아 새 표(Stage2VoiceResult)로 두었다.
- 1단계 마이크 확인은 지금 매번 새로 녹음한다. 사용자별 최근 결과를 저장해 "지난번 값 쓰기"를 주는 방식은 나중 과제다.
